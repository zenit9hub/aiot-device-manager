# 2025년도 겨울학기 혁신공유세미나 과제물 예시

## 과제 2: Modern Cloud 실습 회고 및 트러블슈팅 기록

### 1. 가상 디바이스 실행
- **흔한 트러블슈팅**: `npm install` 중 node.js가 설치되지 않아 오류 발생 → 사전 환경 검토 후 Node.js LTS 버전 설치 및 `npm install` 재실행
  - **회고 메시지**: 미리 런타임을 확인하니 개발 시작 속도가 빨라져서 다음 실습에서는 체크리스트를 먼저 확인하려고 합니다.
- **흔한 트러블슈팅**: 고유한 토픽을 설정하지 않아서 다른 학생과 데이터가 뒤섞이는 문제 → `기기ID/센서유형/타임스탬프` 구조의 토픽 네이밍 규칙을 마련해 분리
  - **회고 메시지**: 토픽 경로를 직접 설계해보니 MQTT 메시지 흐름을 더 잘 이해할 수 있었고, 데이터 품질 관리에 대한 감각도 생겼습니다.

### 2. 브로커 설정
- **흔한 트러블슈팅**: 브로커 주소·포트·인증 정보를 잘못 입력해 연결 실패 → `mqttx`에 복사해둔 설정을 그대로 붙여넣고 TLS/인증서 필요 여부도 함께 확인
  - **회고 메시지**: 브로커 설정을 반복해서 확인해보니 플랫폼 연결의 정합성이 얼마나 중요한지 체감했습니다.
- **흔한 트러블슈팅**: 방화벽/네트워크 정책으로 로컬-클라우드 통신이 차단됨 → `telnet` 혹은 `nc`로 포트 접근 테스트 후 방화벽 예외 등록 요청
  - **회고 메시지**: 네트워크 조건을 점검하면서 인프라 요소도 실습의 일부라는 걸 실감했어요.

### 3. mqttx 툴로 메시지 체크
- **흔한 트러블슈팅**: 구독한 토픽이 없어 메시지 감지 안 됨 → UI에서 Subscribe 상태를 확인하고, QoS 설정도 실험적으로 올려서 안정화
  - **회고 메시지**: MQTT 메시지를 눈으로 확인하니 센서 데이터 패턴이 더 잘 보였고, 디버깅 시간이 확 줄었습니다.
- **흔한 트러블슈팅**: JSON 문자열이 깨져 보이거나 필드가 빠짐 → 디바이스의 payload 포맷을 라인별로 출력하고, 예시 JSON 스키마를 만들어 지키도록 유도
  - **회고 메시지**: 출력 로그를 단순히 보는 것보다 포맷을 정의해두니 그룹 과제에서도 논의 기준이 명확해졌습니다.

### 4. 실제 플랫폼 서비스 로그인 및 디바이스 추가
- **흔한 트러블슈팅**: 파이어베이스 설정을 `.env`에 몰아서 작성하다 보니 API 키가 누락됨 → `.env.sample`을 복사해 필수 키 목록을 채운 뒤 배포 전에 변수 검증 스크립트 실행
  - **회고 메시지**: 첫 `.env` 연동 경험이 신기해서 관련 문서를 더 봤고, 다음에는 자동 검증도 넣어볼 생각입니다.
- **흔한 트러블슈팅**: 디바이스 추가 시 Firestore 보안 규칙 오류 (읽기/쓰기 권한 없음) → 규칙에서 테스트 유저 UID/디바이스 ID를 허용해 문제 해결
  - **회고 메시지**: 룰을 고치고 나서야 디바이스가 보이더군요; API 보안 정책까지 함께 고려하게 되었습니다.

### 5. 플랫폼 서비스에서 디바이스 센서 데이터 체크
- **흔한 트러블슈팅**: 화면에 센서 값이 비어 있음 → 데이터 수집 주기가 너무 길거나 필드 매핑이 맞지 않아 `timestamp`/`value` 필드 확인
  - **회고 메시지**: 실시간 대시보드에 직접 값이 찍히는 걸 보고, 데이터 파이프라인의 끝단도 꼭 검토해야 한다는 걸 느꼈습니다.
- **흔한 트러블슈팅**: 데이터가 오래된 주기로 들어와서 실시간성이 떨어짐 → 디바이스 측에서 전송 간격을 줄이고 MQTT QoS를 1 또는 2로 조절
  - **회고 메시지**: 주기 조정으로 화면 반응이 빨라지자, 학생끼리 피드백을 주고받는 분위기도 생겼습니다.

### 정리
각 단계에서 발견한 오류와 해결 경험을 과제물로 정리하면 수업 중 실습 내용이 잘 정리되고, 향후 운영에서도 동일한 트러블슈팅을 빠르게 할 수 있다는 가치를 강조하세요.
