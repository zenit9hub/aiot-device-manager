# 문서 품질 체크리스트

## 문서 목적
이 문서는 산출물 문서의 품질을 일관된 기준으로 검토하기 위한 체크리스트입니다.  
검토자는 이 문서를 사용해 문서의 완성도, 일관성, 실행 가능성을 빠르게 판단할 수 있습니다.

## 2. 품질 체크 항목
| 체크 ID | 점검 항목 | 판정 기준 (Pass) |
|---|---|---|
| QC-01 | 문서 목적 명확성 | 문서 서두에 2~4줄 목적이 있고 비전공자도 이해 가능 |
| QC-02 | 범위 명확성 | In/Out Scope 또는 대상 범위가 명시됨 |
| QC-03 | 용어 일관성 | 핵심 용어(요구사항, 기능, 아키텍처)가 문서 간 동일하게 사용됨 |
| QC-04 | 추적 가능성 | FBS-SRS-아키텍처 연결이 `06_추적성 매트릭스`에 반영됨 |
| QC-05 | 실행 가능성 | WBS/운영 스크립트 기준으로 실제 강의 진행이 가능함 |
| QC-06 | 검증 가능성 | 요구사항이 검증 방법 또는 수용 기준을 가짐 |
| QC-07 | 최신성 | 기준 브랜치/기준일이 명시되고 최신 상태를 반영함 |
| QC-08 | 형식 통일성 | 문서 정보(버전/작성일/승인자/상태) 형식이 동일함 |
| QC-09 | 변경 이력 관리 | 변경 이력 표가 존재하고 업데이트됨 |
| QC-10 | 링크/참조 유효성 | 참조 문서 경로가 실제 존재함 |
| QC-11 | 코드 근거 명시성 | 핵심 요구사항이 코드 경로 1개 이상과 연결됨 |

## 3. 검토 수행 방식
| 단계 | 내용 | 산출물 |
|---|---|---|
| 1 | 문서 형식 점검(QC-01,02,08,09) | 형식 점검 결과 |
| 2 | 내용 정합성 점검(QC-03,04,06) | 정합성 리뷰 메모 |
| 3 | 운영 가능성 점검(QC-05,07,10) | 운영 리스크 목록 |
| 4 | 최종 판정 | 승인/보완 요청 |

## 4. 판정 기준
- `Pass`: 해당 항목의 기준을 충족함
- `Conditional Pass`: 경미한 수정 후 즉시 승인 가능
- `Fail`: 강의 운영 또는 개발 연계에 영향이 있어 수정 필요
