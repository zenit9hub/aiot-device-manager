# SRS (Software Requirements Specification) - AIoT Device Manager

## 문서 목적
이 문서는 시스템이 충족해야 할 요구사항을 기능/비기능/인터페이스 기준으로 명세하여, 이해관계자 간 해석 차이를 줄이기 위한 문서입니다.  
개발과 테스트의 공통 기준(“무엇이 완료인가”)을 정의합니다.

## 1. 문서 범위
- 대상 시스템: AIoT Device Manager (교육용 MVP)
- 기준 브랜치: `main`
- 기준 단계: Phase 1(Serverless MVP) + Phase 2 확장 포인트 정의
- 비고: 본 문서는 강의 보조 자료의 구버전이 아닌, 현재 리포지토리 코드와 최신 강의 목적 문서를 기준으로 작성함

## 2. 시스템 개요
사용자는 로그인 후 디바이스를 등록/조회/관리하고, MQTT 기반 실시간 데이터를 모니터링한다.  
초기 단계는 Firebase 중심으로 빠르게 동작하며, 이후 Backend+SQL 확장 지점을 갖는다.

## 3. 이해관계자 및 사용자
| 구분 | 설명 |
|---|---|
| 학습 사용자 | 실습을 통해 플랫폼 개발 흐름을 익히는 수강생 |
| 운영자 | 교육 운영 및 결과물 품질 관리 |
| 개발자/멘토 | 코드/설계 타당성 검토 및 기술 지원 |

## 4. 기능 요구사항 (Functional Requirements)
| ID | 요구사항 | 우선순위 | 검증 방법 |
|---|---|---|---|
| REQ-F-001 | 사용자는 Google 로그인으로 인증할 수 있어야 한다. | High | 로그인 성공 이벤트/상태 확인 |
| REQ-F-002 | 사용자는 이메일 기반 로그인할 수 있어야 한다. | High | 이메일 로그인 성공/실패 케이스 확인 |
| REQ-F-003 | 로그인 상태는 세션 단위로 유지되어야 한다. | High | 재접속 후 세션 유지 확인 |
| REQ-F-004 | 인증된 사용자는 자신의 디바이스를 등록할 수 있어야 한다. | High | 등록 후 목록 반영 확인 |
| REQ-F-005 | 사용자는 자신의 디바이스 목록을 실시간으로 조회할 수 있어야 한다. | High | 변경 시 UI 자동 갱신 확인 |
| REQ-F-006 | 사용자는 디바이스 상태를 변경할 수 있어야 한다. | Medium | 상태 변경 API/저장 결과 확인 |
| REQ-F-007 | 사용자는 디바이스를 삭제할 수 있어야 한다. | Medium | 삭제 후 목록 반영 확인 |
| REQ-F-008 | 시스템은 MQTT 메시지를 수신해 표시할 수 있어야 한다. | High | 메시지 로그/상태 패널 확인 |
| REQ-F-009 | MQTT 미연결 시 시뮬레이션 모드로 대체 동작해야 한다. | High | 브로커 URL 미설정 시 동작 확인 |
| REQ-F-010 | 시스템은 환경 구성 점검 체크리스트를 표시해야 한다. | Medium | env/auth/firestore 체크 상태 확인 |
| REQ-F-011 | 시스템은 Phase 2 확장 지점을 안내해야 한다. | Medium | UI/문서에서 확장 포인트 확인 |

## 5. 비기능 요구사항 (Non-Functional Requirements)
| ID | 요구사항 | 목표 |
|---|---|---|
| REQ-NF-001 | 학습 재현성 | 기본 환경에서 실습 흐름이 중단 없이 재현될 것 |
| REQ-NF-002 | 가시성 | 인증/연결/오류 상태가 UI에 명확히 표시될 것 |
| REQ-NF-003 | 보안 기본선 | Firebase Auth 기반 접근제어 원칙을 적용할 것 |
| REQ-NF-004 | 확장성 | Backend/SQL 연계를 위한 구조적 연결 지점이 존재할 것 |
| REQ-NF-005 | 유지보수성 | 기능이 모듈 단위로 분리되어 수정 영향 범위를 예측 가능할 것 |

## 6. 외부 인터페이스 요구사항
### 6.1 인증 인터페이스
- Firebase Auth
- 지원 방식: Google OAuth, Email/Password

### 6.2 데이터 인터페이스
- Firestore 실시간 구독/문서 갱신
- 사용자별 디바이스 컬렉션 구조 사용

### 6.3 메시징 인터페이스
- MQTT over WebSocket
- 기본 토픽: `aiot/devices/#` (환경변수로 변경 가능)

### 6.4 배포 인터페이스
- AWS Amplify 기반 프런트엔드 배포

## 7. 제약 및 가정
- 교육 시간 제약(2일)으로 엔터프라이즈급 운영 상세는 범위 외
- 외부 서비스(Firebase/MQTT/AWS) 계정/설정이 사전에 준비되어야 함
- 브로커/권한 이슈 시 시뮬레이션 모드로 실습 지속

## 8. 수용 기준 (System Acceptance)
- AC-01: 로그인 후 디바이스 목록 조회 가능
- AC-02: 디바이스 등록/상태변경/삭제 기본 흐름 동작
- AC-03: MQTT 메시지 또는 시뮬레이션 데이터가 화면에 반영
- AC-04: 체크리스트로 환경 상태를 설명 가능
- AC-05: 문서상 Phase 2 확장 경로를 설명 가능
