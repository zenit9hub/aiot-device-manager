## 1. 프로젝트 개요
- 프로젝트명: Modern Cloud 기반 AIoT 서비스 플랫폼 설계, 구축 및 배포
- 수행 성격: 교육 과정 기반 MVP 기획/설계/구축/배포 시뮬레이션
- 기준 저장소: `aiot-dev-mgr-cdx` (`main` 브랜치 기준)
- 기준 문서:
  - `(260315) 플랫폼 강의 구성 목적.md`
  - `(260315) 플랫폼 강의 오리엔테이션 가이드.md`
  - `(커리큘럼) Modern Cloud 기반 AIoT 서비스 플랫폼 설계, 구축 및 배포.md`

## 2. 추진 배경
- 교육 과정에서 기획/설계/구축/배포가 분절적으로 이해되는 문제를 개선한다.
- 실제 동작 가능한 코드 리포지토리를 기반으로, 문서 산출물과 구현의 연결을 학습한다.
- 소규모 팀 환경(2~3인 MVP 팀)에서도 재현 가능한 실무형 프로세스를 제시한다.

## 3. 목표
### 3.1 비즈니스/교육 목표
- 수강생이 프로젝트 생애주기(`기획 → 설계 → 구축 → 배포`)를 하나의 흐름으로 설명할 수 있어야 한다.
- 산출물 문서와 코드 구조를 대응시켜, 문서가 실제 개발 의사결정에 기여함을 경험하게 한다.

### 3.2 결과 목표
- 핵심 산출물 5종(RFP/FBS/WBS/SRS/아키텍처 설계문서) 완성
- Firebase Auth + Firestore + MQTT 기반 MVP 기능 흐름 설명 가능
- Phase 2(Backend 연동) 확장 지점을 문서로 명시

## 4. 범위
### 4.1 포함 범위 (In Scope)
- 기획 산출물 작성: 프로젝트 목표, 범위, 이해관계자, 성공 기준 정의
- 설계 산출물 작성: 기능 분해, 요구사항 명세, 아키텍처 설계
- 구현 연계 확인: 현재 리포지토리 코드와 문서 간 대응 관계 정리

### 4.2 제외 범위 (Out of Scope)
- 대규모 엔터프라이즈 운영 상세 설계(24x7 운영, 고가용성 상세 튜닝)
- 실제 상용 SLA 계약/법무 문서
- 전체 백엔드 제품화 완료(본 과정은 확장 방향까지 정의)

## 6. 요구 성과(납품 관점)
- 문서 품질:
  - 문서별 목적 명시
  - 요구사항/기능/아키텍처 간 추적 가능성 확보
- 교육 품질:
  - 강의 시간 내 설명 가능한 구조
  - 수강생이 문서 기반으로 구현 흐름을 재현 가능

## 7. 성공 기준 (Acceptance Criteria)
- 5개 문서가 상호 모순 없이 연결된다.
- `SRS`의 주요 요구사항이 `FBS` 및 `아키텍처 설계문서`에 추적된다.
- 현재 코드 구조(인증/디바이스/MQTT/배포)와 설계 문서의 대응이 확인된다.
