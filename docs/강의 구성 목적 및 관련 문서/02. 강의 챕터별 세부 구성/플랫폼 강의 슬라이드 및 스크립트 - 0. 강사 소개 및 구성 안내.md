### Slide 2. Modern Cloud 기반 AIoT 서비스 플랫폼 설계, 구축 및 배포

     2) 요구사항 분석, 명세화 ✚
     3) 기술 요소 분석 ✚
     4) AIoT 서비스 플랫폼 개요

     1) 인프라 구조 설계 ✚
     2) 로그인 인증 설계 ✚
     3) 입출력 구조 설계 ✚
     4) 형상 관리 (Git)

그다음 기술 요소 분석에서는 이 서비스를 구성하기 위해 어떤 기술들이 필요한지, 왜 그런 선택이 필요한지를 함께 살펴보겠습니다.

로그인 인증 설계에서는 단순 로그인 기능만이 아니라, 인증과 권한 구조를 어떤 방식으로 가져갈지 함께 보겠습니다.  
입출력 구조 설계에서는 사용자 요청, 디바이스 데이터, 시스템 처리 흐름이 어떻게 연결되는지 설계 관점에서 정리하겠습니다.

마지막 형상 관리 부분은 단순히 Git 명령을 배우는 것에 그치지 않고, 기획과 설계 산출물을 어떻게 관리하고 이어갈 것인지까지 함께 생각해보는 시간으로 이해하시면 됩니다.

정리하면, 오늘 1일차는 무엇을 만들 것인가를 문서로 정리하고, 그것을 어떤 구조로 구현할 것인가를 설계하는 흐름으로 진행됩니다.

### Slide 3. Modern Cloud 기반 AIoT 서비스 플랫폼 설계, 구축 및 배포

다. AIoT 서비스 플랫폼 구축
     1) 로그인 인증 연동 (Firebase Auth)
     2) 인프라 구축 (AWS 기반)
     3) 데이터관리 시스템(MariaDB)
     4) 백업 복구 시스템

라. AIoT 서비스 플랫폼 배포
     1) Docker, K8S 기본 개념
     2) 형상 관리 (Git)
     3) 관리 매뉴얼 작성

``` 스크립트
이어서 2일차 강의 구성을 안내드리겠습니다.

2일차는 1일차에 정리한 기획과 설계를 바탕으로, 실제 구축과 배포 단계로 넘어가는 과정입니다.  
즉, 문서와 구조로 정리한 내용을 실제 서비스 형태로 연결해보는 날이라고 보시면 됩니다.

먼저 구축 파트에서는 로그인 인증 연동을 통해 사용자 인증이 실제 서비스에서 어떻게 동작하는지 구현해보겠습니다.  
이 과정에서는 Firebase Authentication을 활용하여 비교적 빠르고 안정적으로 인증 기능을 연결하는 방식을 살펴보겠습니다.

다음으로 인프라 구축에서는 AWS 기반 환경을 중심으로, 매니지드 서비스를 활용해 서비스를 어떻게 구성하고 운영 부담을 줄일 수 있는지 함께 보겠습니다.  
데이터관리 시스템에서는 MariaDB와 같은 관계형 데이터 저장소가 어떤 역할을 하는지 이해하고, 서비스 구조 안에서 데이터 관리가 어떻게 이루어지는지 정리하겠습니다.  
백업 복구 시스템에서는 운영 과정에서 데이터 안정성을 어떻게 확보할 것인지 기본 개념과 방향을 함께 살펴보겠습니다.

이후 배포 파트에서는 Docker와 Kubernetes의 기본 개념을 통해, 서비스를 어떤 방식으로 배포하고 확장할 수 있는지 이해해보겠습니다.  
여기서는 단순 도구 소개에 그치지 않고, 실제로 어떤 상황에서 이런 기술이 필요한지까지 연결해서 보겠습니다.

형상 관리 부분 역시 구현 산출물을 버전 관리하는 것뿐 아니라, 기획, 설계, 구축 결과물이 어떻게 이어지고 관리되어야 하는지까지 함께 생각해보는 관점으로 설명드리겠습니다.  
마지막으로 관리 매뉴얼 작성에서는 서비스를 만들고 끝내는 것이 아니라, 이후 운영과 유지보수를 위해 무엇을 문서화해야 하는지도 함께 정리하겠습니다.

정리하면, 2일차는 1일차의 설계를 실제 구축과 배포로 연결하면서, MVP 서비스가 운영 가능한 형태로 정리되는 흐름으로 진행됩니다.
```

유의사항도 하나만 분명히 말씀드리겠습니다.

기획부터 설계, 구축, 배포까지 전체 흐름을 한 번에 이해하는 과정입니다.
따라서 오늘은 모든 세부 기능을 다 외우는 것보다,
각 단계가 왜 필요한지와 어떻게 연결되는지를 이해하는 데 집중해주시면 좋겠습니다.

마지막으로 강의 종료 시점에 기대하실 수 있는 결과입니다.
강의가 끝나면 플랫폼 기획부터 배포까지의 전체 구조를 설명하실 수 있고,
요구사항과 설계 문서가 실제 구축 단계와 어떻게 연결되는지 이해하실 수 있으며,
Firebase 기반 MVP와 이후 Backend, RDS, Docker 같은 확장 구조가 왜 필요한지도 판단하실 수 있게 되는 것을 목표로 합니다.

그럼 이제 본격적으로,
플랫폼이란 무엇인가부터 시작하겠습니다.
