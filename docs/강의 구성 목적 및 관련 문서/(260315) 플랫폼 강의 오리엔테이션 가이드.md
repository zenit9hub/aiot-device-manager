# Modern Cloud 기반 AIoT 서비스 플랫폼 설계, 구축 및 배포
## 수강 전 오리엔테이션 가이드

> **2일 14시간 집중 과정 | 기획부터 배포까지 하나의 흐름으로 이해하는 AIoT 플랫폼 실무 입문 과정입니다.**

---

## 1. 이 강의는 어떤 과정인가요?
본 과정은 AIoT 서비스 플랫폼을 `기획 → 요구사항 분석 → 설계 → 구축 → 배포`의 흐름으로 이해하도록 구성된 강의입니다.  
개별 기술을 단편적으로 배우기보다, 하나의 MVP 프로젝트가 어떤 문서와 구조를 거쳐 실제 서비스 형태로 연결되는지를 경험하는 데 초점을 둡니다.

강의는 AIoT Device Manager 샘플 프로젝트와 기획·설계 문서를 기반으로 진행되며, 필요에 따라 자신의 아이디어를 반영해 확장해서 생각해보실 수도 있습니다.

---

## 2. 이 강의에서 얻게 되는 것
- 플랫폼의 개념과 AIoT 서비스 플랫폼의 특징 이해
- 요구사항 분석, 기술 요소 분석, 설계 문서의 흐름 이해
- Firebase Auth와 Firestore를 활용한 빠른 MVP 구축 경험
- AWS 기반 배포 흐름과 운영 관점 이해
- Docker, Kubernetes 등 확장 기술의 기본 개념 정리
- Firebase 중심 MVP와 Backend/RDS 기반 확장 구조의 차이 이해

## 3. 강의 구성

### 1일차: 기획 + 설계
**오전**
- 강의 오리엔테이션 및 전체 흐름 안내
- 플랫폼 개념 이해
- 요구사항 분석 및 명세화
- 기술 요소 분석
- AIoT 서비스 플랫폼 개요 정리

**오후**
- 인프라 구조 설계
- 인증·권한 구조 설계
- 입출력 및 데이터 구조 설계
- 기획·설계 산출물 형상관리 관점 정리
- 2일차 실습 환경 구축

### 2일차: 구축 + 배포
**오전**
- 1일차 산출물 리뷰
- Firebase 프로젝트 설정
- 로그인 인증 연동
- AIoT Device Manager MVP 구축 실습

**오후**
- AWS 기반 인프라 및 Amplify 배포 흐름 이해
- 데이터 관리 시스템과 백업·복구 개념 정리
- Docker, Kubernetes 기본 개념 학습
- 관리 매뉴얼 및 운영 관점 정리

## 4. 미리 알고 오시면 좋은 점
본 과정은 전체 흐름을 이해하는 데 중점을 두고 있습니다.  
따라서 각 기술의 고급 운영 실무를 모두 깊게 다루는 과정은 아니며, 기획부터 배포까지 연결되는 구조를 빠르게 파악하는 데 더 적합합니다.

특히 다음과 같은 분들께 잘 맞습니다.
- 플랫폼 프로젝트의 전체 구조를 빠르게 이해하고 싶은 분
- 자신의 직무 외 영역까지 함께 이해하고 싶은 분
- 적은 인원으로 MVP를 빠르게 기획하고 구현해야 하는 환경에 있는 분

## 6. 강의 운영 방식
- 기본적으로 `50분 진행 + 10분 휴식` 흐름으로 운영합니다.
- 질문은 강의 중에도 언제든 가능합니다.
- 실습은 샘플 프로젝트 기반으로 진행하지만, 구조를 이해한 뒤 각자 응용 방향도 함께 생각해보는 방식으로 진행합니다.
- 실습 중에는 환경 설정, 인증, 배포 이슈에 대한 트러블슈팅 지원을 제공합니다.

## 7. 유의사항
- 이 과정은 대규모 엔터프라이즈 시스템 전체를 구현하는 심화 과정이 아닙니다.
- 대신, 실제 서비스 플랫폼이 어떤 단계와 산출물을 거쳐 만들어지는지 전체 흐름을 익히는 과정입니다.
- 모든 내용을 완벽히 익히는 것보다, 각 단계가 왜 필요한지와 어떤 순서로 연결되는지를 이해하는 것이 더 중요합니다.

## 8. 강의 종료 시점에 기대할 수 있는 결과
강의가 끝나면 수강생은 다음과 같은 상태에 도달하는 것을 목표로 합니다.

- 플랫폼 기획부터 배포까지의 전체 구조를 설명할 수 있습니다.
- 요구사항과 설계 문서가 구축 단계와 어떻게 연결되는지 이해할 수 있습니다.
- Firebase 기반 MVP를 어떤 상황에서 빠르게 활용할 수 있는지 설명할 수 있습니다.
- 서비스가 성장할 때 Backend, RDS, Docker 같은 구조가 왜 필요한지 판단할 수 있습니다.

### 8.3 발표용 설명 스크립트 (요약)
이 도표는 `코어 실습`과 `선택 챌린지`를 한 장에서 구분해 보여줍니다.
먼저 가상 온도 센서가 EMQX 브로커로 MQTT 메시지를 발행하고, MQTTX로 구독 테스트를 수행해 메시징 경로를 검증합니다.

메시징이 확인되면 플랫폼 코어로 넘어갑니다.
FE Web은 MQTT 스트림을 수신하고, Firebase Auth로 사용자 인증을 처리하며, Firestore를 기본 데이터 저장소로 사용합니다.
Storage는 파일 처리 시나리오에서 선택적으로 확장할 수 있습니다.

로컬 검증이 끝나면 같은 FE를 AWS Amplify에 배포해 운영 경로를 재현합니다.
점선으로 표시한 하단은 확장 챌린지로, 로컬 BE를 붙여 HTTPS API 경로를 만들고 AWS RDS 또는 로컬 Docker DB까지 연결해 Phase 2 아키텍처를 실습합니다.
본 과정의 핵심 목표는 2일 14시간 안에 전 기능 완성을 하기보다, 기획-설계-구축-배포의 연결 원리를 체득하는 것입니다.
